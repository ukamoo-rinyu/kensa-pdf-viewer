# 開発メモ — 実装状況・決定事項・ハマりどころ

ここには**実装した内容・決定事項・次にやること**を記録する。

経緯: [mail-pdf-viewer](https://github.com/ukamoo-rinyu/mail-pdf-viewer) の「一般資料PDF(しおり階層)」
モード向けの拡張として試作を始め、2026-09-28に単独のビューアーとして独立させた。
しおりの読み取りは mail-pdf-viewer の `parser.py` から必要部分を `pdf_sections.py` に取り込んでいる。
元アプリの `db.py`(PDFの横にSQLiteの索引を作る)は使わない。検査対象のPDFが置かれた共有フォルダに
余計なファイルを残さないため、しおりは毎回PDFから直接読む。

## 実装済み(フェーズ1: 指摘の記録・一覧・Excel書き出し・削除)

- **`indications.py`**: `Anchor`(しおりパス+相対ページ+座標比率+近傍テキスト)、`Indication`、
  `IndicationStore`(JSON保存/読込、`merge()`でid基準の冪等な統合)。
- **`kensa_window.py`**: メインウィンドウ。
  - `MarkerPageView`: PDFを1ページずつ画像として表示し、クリックでマーカー(付箋ピン)を置く独自ビュー。
  - マーカー配置モード(トグルボタン)はONのまま維持され、続けて複数箇所に置ける。
  - 既存マーカーをクリックすると内容編集ダイアログが開く(配置モードのON/OFFに関わらず)。
  - 指摘一覧テーブル: シングルクリックでページ移動、ダブルクリックで編集ダイアログ。
  - 区分(要修正/要確認/軽微/質問)・状態(未対応/修正済/確認済/再指摘)。
- **`export_excel.py`**: 指摘一覧をxlsxへ(ヘッダー色付け・テーブル化)。受注者に渡す指摘事項一覧になる。
- 指摘の削除: 編集ダイアログ(`IndicationDialog`)に「この指摘を削除」ボタンを追加。
  クリック時に確認ダイアログを挟んでから`delete_requested`フラグを立てて`accept()`し、
  呼び出し側(`KensaWindow._edit_indication`)がフラグを見て`IndicationStore.delete()`を呼ぶ
  (通常の更新と同じacceptedルートに乗せ、専用のDialogCodeは使わない設計)。

## 実装済み(フェーズ2: 新旧2画面表示)

- **`matching.py`**: 再提出版PDFへの指摘アンカー照合。
  完全一致 → あいまい一致(表記ゆれ正規化+`difflib`類似度) → 近傍テキスト全文検索 → 照合できず、
  の4段階。`normalize_title()`は`bookmark_diff.py`とも共有。
- **`bookmark_diff.py`**: しおり構成の差分(追加された章/削除された章/名前が変わった章)。
  しおりパスの完全一致→残りをあいまい一致(`RENAME_THRESHOLD=0.6`)で「名称変更」と推定。
- **`compare_window.py`**: 旧版(左)・新版(右)を並べる独立ウィンドウ(`KensaWindow`の
  ツールバー「新旧2画面で比較…」から開く)。
  - 左パネルはタブ切り替え: 「指摘一覧」(クリックで旧新とも該当箇所へジャンプ)と
    「しおり差分」(追加/削除/名称変更、クリックでジャンプ)。
  - 照合が「照合できず」の場合は**新版側を動かさない**。差分・照合はあくまで当たりをつける
    補助であることを画面上部の常時バナーで明示。

## 実装済み(フェーズ3: 差分の可視化)

- **`page_diff.py`**(Qtに依存しない比較ロジック):
  - `pair_pages()`: 旧新ページの対応付け。ページ番号ではなく「しおり区間(完全一致 or 名称変更と
    推定した章)+区間内の位置」で決める。区間内のページ数が同じなら先頭から順に、違う場合は
    ページ内容の類似度で順序を保った対応(重み付きLCS)を取り、途中の挿入・削除を吸収する。
    対応が取れないページは「追加/削除されたページ」として扱い、推測で別ページを指さない。
  - `PageDiffer.diff()`: 1ページ対の比較。**文字差分**は1文字単位(日本語に単語区切りがないため)で
    difflibにかけ、変更文字を行ごとの矩形にまとめる。**画素差**はページを120マス幅の灰色格子に縮小
    して比べ(±1マスのずれは許容)、**文字のある領域は除外**する。写真の差し替えのように文字が
    同じままの変更を拾うのが役割で、改行位置のずれで全面が差分になるのを避けるため。
- **`compare_window.py`**: 差分バーを追加。
  - 「差分を表示」: 旧版側=赤(消えた・変わった文字)、新版側=緑(増えた・変わった文字)、
    紫=図・画像の変化、の枠を重ねる(`MarkerPageView.set_overlays`。ページ移動で自動的に消える)。
  - 「ページ送りを連動」: 片側をめくると`pair_pages`で対応付けたもう片側へ追従。OFFにすると
    表示中のページ同士をそのまま比べる(対応付けと違う組なら注記を出す)。
  - 「前の差分/次の差分」: 変更のあったページ対だけを順に送る(時間がかかる場合は進捗・中止あり)。
  - 差分が出なかったページは「修正されていない、という意味ではありません」と表示する。
  - 指摘一覧からのジャンプも、新版側は区間の先頭ではなく対応付けたページへ開くようにした。
- **KojiPDFのしおり名末尾「_開始ページ_ページ数」は照合・差分のキーから除く**
  (`matching.strip_page_suffix` / `bookmark_diff.section_key`)。除かないと、途中に1ページ
  挟まっただけで後ろの全章が「名称変更」になり、指摘の照合も完全一致しなくなる(京都市.pdfで
  56章が名称変更扱いになった)。除くと同名になる章(同じ親の下の「●」など)は出現順で区別する。
- **中身が同一のページは指紋で即判定**(`PageDiffer._fingerprint`: 描画命令+画像の圧縮データの
  ハッシュ)。大きな画像の展開が処理時間の大半だったため。区間内の対応付けも、先頭・末尾の
  同一ページを先に対応させ、残りだけを類似度で比べる。
- 文字のページがスキャン画像に置き換わった(文字情報が消えた/現れた)こと自体を変更として知らせる。
- 文字は比較前にNFKC正規化する(全角「１」と半角「1」の違いを差分にしない)。
- **評価用ツール `devtools/`**: `make_kyoto_new.py`が京都市.pdf(京都市都市計画マスタープラン。
  リポジトリには含めない。リポジトリの1つ上のフォルダに置く前提)から再提出版を模した新版を作り
  (文言修正3・ページ追加/削除・しおり名変更・図の修正・再スキャン2・しおり名末尾の番号振り直し)、
  `eval_kyoto.py`が検出/見逃し/誤検出・速度・既存指摘の照合を集計する。しきい値を調整したら
  これで回帰確認する。出力は`devtools/out/`(git管理外)。
- 評価結果(2026-09-28): 京都市.pdf(173ページ)で仕込んだ変更8件をすべて検出、誤検出0件、
  既存指摘3件はすべて完全一致。比較画面を開くまで約4秒、全ページ比較約3秒。
  実物の新旧(一級建築士試験の合格基準 2024/2025)でも年度・合格点・解答表の変更を検出。

## 重要な設計判断・ハマりどころ

- **`QPixmap.setDevicePixelRatio()`は使わない。** 高解像度で描いてから`QLabel`に渡す際、
  明示的な`devicePixelRatio`を画面のスケーリング設定と組み合わせると、PySide6側が
  ピクセルデータごと想定外に縮小してしまい、マーカー座標とページ表示がずれる不具合が
  実機相当の環境(`devicePixelRatioF()`が1.5などの環境)で再現した。
  今は「高解像度で描く→`QPixmap.scaled()`で表示サイズへ明示的に縮小する」方式にしており、
  `_base_pixmap`のサイズは常に`label`の表示サイズ(dpr=1相当)と一致させている
  (`MarkerPageView.render_current_page`のdocstring参照)。
- **UIの見た目のバグは、内部状態のassertだけでは見つからない。** マーカー位置・サイズの
  不具合は`QWidget.grab()`でスクリーンショットを撮り、Readツールで目視確認して初めて
  原因が特定できた。今後もUIの見た目に関する修正は、可能な限りスクリーンショットで
  確認してから完了報告すること。
- **`QPdfDocument.render()`は、ページ自身が何も描いていない領域をalpha=0(透明)で返す(白ではない)。**
  そのまま`QPixmap.fromImage()`すると、透明部分が`QLabel`の背景色を透かして見えてしまい、
  PDFページと周囲のビューアー背景の境目が分からなくなる不具合があった。
  `MarkerPageView.render_current_page`で、レンダリング直後に不透明な白の`QImage`へ
  `QPainter.drawImage()`で合成してから`QPixmap`化することで解消した(縮小表示より前に行う)。
- マーカー配置モード中は、既存マーカーへの当たり判定を無視して常に新規マーカーを作る
  (`MarkerPageView._placement_mode`)。ヒット判定を優先すると、近接した場所に2つ目を
  置こうとしたときに1つ目の編集に化けてしまう不具合があったため。
- 指摘のアンカーはページ番号ではなく、しおりパス+相対ページ+座標比率(0〜1)+近傍テキストで持つ
  (最重要の設計判断)。絶対ページは表示用の参考値であり照合には使わない。
